# Glossary — 272 Terms

Extracted from [the roadmap](ai-salesforce-architect-roadmap.html) glossary tab, grouped by track and alphabetized. Greppable and extendable — **add new terms here as you meet them**, in the right section, keeping alphabetical order. If a term deserves depth, it also earns a flashcard in its topic folder.

> **Currency:** definitions reflect **Summer '26 (API 67.0)**, the current release as of 2026-08-02. Where a term changed meaning in 2026, the entry says so — knowing the old meaning is what stops you answering an exam question from 2025 memory. Running detail and sources live in [05-release-radar/](05-release-radar/README.md).

## Salesforce AI

| Term | Definition |
|---|---|
| A2A (Agent-to-Agent Protocol) | Open protocol for agents built on different platforms to discover and call each other. Examinable: part of the Agentforce Specialist *Multi-Agent Interoperability* section — **weight disputed, 5% or 15% depending on the source**. In MuleSoft Agent Fabric, A2A traffic is governed at Omni Gateway. |
| ADLC (Agent Development Lifecycle) | Salesforce's five-phase lifecycle for agents: Ideation & Design → Development (**inner loop**) → Testing & Validation → Deployment → Monitoring & Tuning (**outer loop**). Differs from SDLC in that deployment is day one, drift is expected, and token economics are a test result. Also the name of the `agentforce-adlc` research repo — say which you mean. |
| Agent Action | A unit of work an agent can execute — an autolaunched Flow, invocable Apex method, prompt template, Apex REST endpoint, `@AuraEnabled` method, or external API call. |
| Agent Broker | MuleSoft Agent Fabric's routing service: groups agents and tools into business domains and delegates tasks across A2A-compliant agents using graph-based routing. **Status disputed** — GA per launch coverage, Beta per April 2026 coverage. |
| Agent Fabric (MuleSoft) | The control plane for agents you didn't build — one pane of glass to register, govern, route and observe every agent and MCP endpoint across vendors. Four pillars: **Agent Registry** (discovery), **Omni Gateway** (governance), **Agent Broker** (orchestration), **Agent Visualizer** (observation). Launched Sept 2025; MuleSoft-licensed, **not** part of an Agentforce SKU. |
| Agent Network | A multi-agent composition in Agent Fabric declared in **YAML** — which agents, brokers, LLMs and MCP servers participate — deployed to CloudHub 2.0. Makes topology a versionable artifact. |
| Agent Registry | Agent Fabric's catalog of every agentic asset: custom agents, SaaS-embedded agents, MCP servers, A2A endpoints. **Federated** — anyone can run a registry and registries reference each other, DNS-shaped rather than a single corporate directory. |
| Agent Scanner | Agent Fabric component that auto-discovers and catalogs agents across **Agentforce, Amazon Bedrock, Google Vertex AI and Microsoft Copilot Studio**. GA January 2026. The shadow-agent finder. |
| Agent Script | The language agents are authored in since 2026: human-readable, compiles to portable JSON, blends deterministic rules (conditionals, explicit hand-offs) with LLM reasoning. Open source, Apache 2.0. **Replaced topic-and-instruction configuration as the default authoring model.** |
| Agentforce | Salesforce's platform for building autonomous AI agents that plan and execute tasks across CRM. In 2026 the platform umbrella is **Agentforce 360**. |
| Agentforce Builder | The current agent authoring UI, built around Agent Script. Since the week of **July 13, 2026** the *New Agent* button opens only this — the legacy builder can still edit existing agents but cannot create new ones. |
| Agentforce Commerce | Three prebuilt commerce agents, **GA July 6 2026**: **Shopper** (B2C storefront, discovery→checkout→service), **Buyer** (B2B via WhatsApp/SMS), **Merchant** (back-office catalogue in natural language). Sells natively inside ChatGPT with the catalogue synced from Business Manager — but **checkout stays on the merchant's own site**. |
| Agentforce Contact Center | Salesforce's native CCaaS, **GA 2026-02-23** (Enterprise Connect 2026), unifying voice, digital channels, CRM data and AI agents in one system. Note the position: Salesforce partners with Genesys/Five9/NiCE at the Voice layer and competes with them here. |
| Agentforce Coworker | **Beta (announced 2026-05-21, no GA date).** An agent embedded in the search bar — Salesforce and Slack today; Teams, ChatGPT, Claude and web later. **You author nothing**: it inherits the org's sharing rules, FLS and permissions, so what it can answer is a governance question, not a configuration one. Searches CRM, Data 360 DMOs and Slack, then routes to specialized agents to act. |
| Agentforce Data Library (ADL) | A managed grounding store: indexes Knowledge articles or uploaded files into a vector index and exposes a retriever for RAG. Lifecycle is scriptable via the ADL Connect API (Beta). |
| Agentforce Specialist | Salesforce certification for building, configuring and deploying agents. Restructured around how agents *think, interact and collaborate*, with a new AI Agents domain and a Multi-Agent Interoperability section. |
| Agentforce Vibes | Salesforce's agentic IDE (**2.0 is Developer Preview**): plans before acting, Plan Mode, MCP integration, built-in Skills and Rules, live LWC previews, current Claude and GPT models in one picker. Free in every Developer Edition org since April 2026. |
| Agentforce Voice | Autonomous inbound **and outbound** calls over **PSTN or SIP trunking** — Salesforce's replacement for the IVR. Live transcription into Salesforce Voice with human takeover mid-call; **barge-in** supported. Amazon Connect is native; Five9, Genesys, NiCE and Vonage connect via **Partner Telephony**. A voice action costs **30 Flex Credits** vs 20 standard. **US/Canada only as of early 2026**, global languages Beta. GA dates conflict — see [12-voice-and-contact-center](02-salesforce-ai/12-voice-and-contact-center/notes.md). |
| Apex Prompt Grounding | Supplying a prompt template's data from Apex instead of merge fields, via `@InvocableMethod(capabilityType=…)`. The platform calls the method **during prompt resolution**, and the return value is not a result — the `Response` class exposes `@InvocableVariable public String Prompt`, whose contents are spliced into the prompt. Capability types: `PromptTemplateType://einstein_gpt__salesEmail`, `__fieldCompletion`, `__recordSummary`, and `FlexTemplate://<template_API_Name>` → [SF/02-apex · 31](../SF/02-apex-and-triggers/31-apex-grounded-prompt-templates.md). |
| Atlas Reasoning Engine | The "brain" of Agentforce: interprets a request, plans steps and chooses actions. **Version 3.0 routes to subagents by reading their descriptions** rather than following a fixed decision tree. |
| BYOM (Bring Your Own Model) | Connecting an external foundation model (e.g. Claude on Amazon Bedrock) so Salesforce features call it through your own endpoint. |
| ConnectApi.EinsteinLLM | The Apex class for invoking a prompt template in code: `generateMessagesForPromptTemplate` (API 60.0) and `getPromptTemplates` (API 62.0). **The 67.0 reference lists only those two** — the raw `generateMessages` path in most 2024 tutorials is absent from it. **It publishes no `setTest*` methods**, so it cannot be mocked by the documented ConnectApi convention, by `HttpCalloutMock`, or by the Stub API → [SF/02-apex · 32](../SF/02-apex-and-triggers/32-invoking-prompt-templates-from-apex.md). |
| Custom Lightning Type | A purpose-built UI attached to an agent action's structured output. Defined once, renders idiomatically everywhere — LWC on desktop, native UI in the mobile app. |
| Custom Scorer | A user-defined quality metric graded against live agent sessions (Beta). Deployable as `aiAgentScorerDefinitions` metadata, so evaluation lives in source control. |
| Data Masking | Trust Layer step that replaces PII in a prompt with placeholder tokens before it leaves Salesforce, then re-inserts real values in the response. |
| Data Services Credits | The consumption unit for **data** work — data queries, unstructured data processed, intelligent processing — as distinct from **Flex Credits**, which cover prompts. Both can be drawn by the same feature; Agentforce Coworker bills against each for different operations. |
| Dynamic Grounding | Injecting live CRM or Data 360 data into a prompt at runtime so the model answers from your data instead of general knowledge. |
| Einstein | Umbrella brand for Salesforce's AI features, spanning older predictive tools and current generative capabilities. |
| Einstein Copilot | **Historical.** The predecessor conversational CRM assistant, folded into Agentforce. You'll still meet the name in 2024–25 material; it is not current product vocabulary. |
| Einstein Request | The billing unit for generative AI consumption. Relevant to Apex because **every `aiplatform.ModelsAPI` call is billed as one**, which makes a loop over records a line-item cost rather than only a governor concern → [SF/02-apex · 33](../SF/02-apex-and-triggers/33-models-api-in-apex.md). Distinct from **Flex Credits**, which meter agent actions. |
| Einstein Trust Layer | The security layer between Salesforce and LLM providers: prompt-injection defence, data masking, secure retrieval, zero retention, toxicity scoring, audit trail. |
| Eval Studio (`sf-pi`) | **Local-first** review and execution workspace for source-controlled Agent Script Eval Suites, Release Eval Contracts and persisted run evidence, added in `sf-pi` **v0.253.0** (2026-08-03). *Local-first* is the design claim: it consults Salesforce only to resolve a version or to execute, so review and triage cost no org call. |
| Flex Credits | The consumption billing unit for Agentforce and Data 360, drawn from one pooled balance. ~$500 per 100,000 credits; a standard action is 20 credits (~$0.10). **Billed per action, not per conversation.** |
| Guided Determinism | Agent Fabric's April 15 2026 capability: goal-based LLM reasoning paired with **codified handoff rules and human checkpoints**. Hybrid Reasoning's design point applied at the network layer instead of inside one agent. Shipped as "Agent Script for Agent Broker" — **not** the Agentforce authoring language of the same name. |
| Help Agent (Agentforce) | Prebuilt self-service support agent, **GA July 2026** — guided setup in "six clicks or less", web/text/voice from one screen, alongside a Customer Service Portal rebuilt as a single conversation bar. Billed **pay-per-resolution**. Salesforce's own benchmark: 4.3M inquiries, 70% resolved on `help.salesforce.com`. |
| IL5 (Impact Level 5) | The U.S. Department of Defense cloud impact level covering **Controlled Unclassified Information (CUI)** and **unclassified National Security Systems (NSS)** data — one step below classified. **Agentforce 360 was announced as IL5-authorized on 2026-08-05**, hosted on **AWS GovCloud** and delivered through Missionforce National Security. Read it as **environment-scoped, not feature-scoped**: it says Agentforce may run in that boundary, not that every feature is available there. Government Cloud Plus already excludes Agentforce Coworker, Agentforce Vibes and ApexGuru. |
| Missionforce National Security | Salesforce's **defense and intelligence vertical estate** — the purchasable product behind the IL5 announcement and the VA's $1.6B Agentic ELA. "Agentforce 360" is the portfolio name; Missionforce is what a government customer actually buys. First IL5 deployment is **U.S. Army Human Resources Command**. |
| Hybrid Reasoning | The Agent Script design point: you dial how much of an agent is deterministic business logic versus left to model reasoning. |
| Inner loop / outer loop | ADLC vocabulary. **Inner loop** = the tight build-and-try cycle run many times a day. **Outer loop** = the slow cycle of monitoring production and feeding improvements back. The outer loop is what catches drift — and **drift has no commit**. |
| Instructions (Guardrails) | Natural-language rules constraining agent behavior — what to always do, never do, how to respond. In Agent Script these become explicit script constructs rather than free-text fields. |
| Model Builder | Tool to register and configure LLMs — Salesforce-hosted or bring-your-own via Bedrock/Vertex — for use across Prompt Builder and Agentforce. |
| Models API | The lowest-level generative surface: a prompt in, a completion out, no prompt template involved. In Apex it is the **`aiplatform.ModelsAPI`** class — `createGenerations`, `createChatGenerations`, `createEmbeddings`, `submitFeedback`. **Instance methods, not static**, and generated from **External Services**, so every call is an **Apex callout** against the per-transaction budget as well as a billed Einstein Request → [SF/02-apex · 33](../SF/02-apex-and-triggers/33-models-api-in-apex.md). |
| Multi-Agent Orchestration (MAO) | An **orchestrator agent** connecting to specialized subagents and presenting one point of contact, with shared context across channels. GA June 15, 2026. |
| Omni Gateway | **Formerly Flex Gateway** — same MuleSoft runtime, renamed and expanded to govern AI agents, MCP and A2A traffic alongside APIs. The rename is non-breaking and cosmetic (1.13.0), so CI/CD is unaffected; both names still circulate. In Agent Fabric it is the runtime policy layer between agents and the systems they reach. |
| Pay-per-resolution | Outcome-based pricing introduced with the Agentforce Help Agent: **$2 per issue resolved autonomously end-to-end**. Human escalations and negative-feedback sessions are free, and consumption during the interaction is unmetered. Third commercial model alongside Flex Credits and a negotiated **AELA** (Agentic Enterprise License Agreement — the VA's $1.6B/3yr, July 2026). |
| Prompt Builder | Declarative tool for creating reusable prompt templates that merge CRM record data and grounding sources before calling an LLM. Templates can also be exposed as MCP prompts. |
| Prompt Template | A reusable, versioned prompt definition with merge fields, resolved with live data at runtime. |
| Seed Profile (Agent Script Eval) | A source-only declaration inside one eval suite that resolves **exactly one row** from **one bounded read-only SOQL query** against the Eval Run Target org and maps scalar fields into Scenario context variables. Added in `sf-pi` **v0.253.0**. Kills hard-coded record IDs in eval suites: zero rows, several rows, null or mistyped fields **fail before the run is created**, and a reused profile executes **once per run**, not once per scenario. |
| Subagent (Agentforce) | A specialized agent invoked by an orchestrator. Its **description is the routing contract** — Atlas 3.0 reads it to decide routing, so write it like an API doc, not a label. |
| Topic (Agentforce) | **Legacy authoring concept.** A job category grouping related actions and instructions. Still present in agents built before mid-2026; superseded by Agent Script for new work. |
| Triggered Agent | An agent that fires on a defined event — a deal stage change, a Data 360 customer signal — rather than on a human utterance. |
| Turn Response Integrity | `sf-pi` **v0.257.0** eval policy (`sf_pi.turn_response_integrity`) that fails a turn emitting more than `max_nonempty_llm_contents` non-empty LLM completions — the **double-texting** check. Deterministic: it parses `lastExecution.llmEvents` with **no model call**, and at `severity: "error"` fails local preflight **before** any org call. Findings land in a separate `response_integrity_evidence` field, and the policy is **never sent to the Evaluation API**. |
| Zero Data Retention | Guarantee that model providers processing prompts via the Trust Layer don't store them or use them for training. |

## Data 360

> Formerly **Data Cloud**. The folder is still named `01-data-cloud/` so existing links and the dashboard keep working — the product name is Data 360.

| Term | Definition |
|---|---|
| Accelerated Data Ingest | Real-time CRM data into Data 360 with no pipeline lag (**GA**, Summer '26). Removes the most common cause of an agent answering confidently from stale state. |
| Activation | Publishing a segment or data to a target — Marketing Cloud, ad platforms, CRM — where action happens. |
| Calculated Insight | A metric (e.g. lifetime value, engagement score) computed over Data 360 data on a schedule with a SQL-like definition. |
| CDP (Customer Data Platform) | System category that unifies customer data into persistent profiles. Data 360 began as Salesforce's CDP; **the 2026 framing is a context engine that grounds agents**, which is a bigger job than a CDP. |
| Code Extension | Custom **Python** scripts and functions deployed to isolated containers inside Data 360. Current uses: batch data transformations and **custom chunking logic** on search index creation. |
| Data 360 | Salesforce's lakehouse-based platform that ingests, harmonizes, unifies and activates data from any source, and grounds AI agents in it. Renamed from Data Cloud at Dreamforce 2025. |
| Data 360 Consultant | The certification covering ingestion, modeling, identity resolution, insights, segmentation and activation. Renamed from *Data Cloud Consultant* on 2026-03-27; **exam code `Data-Con-101` unchanged**. |
| Data Graph | A precomputed, denormalized view of related data around a profile, built for millisecond real-time reads by agents and personalization. |
| Data Kit | The DevOps package that promotes Data 360 configuration — including code extensions and the data transforms built from them — from sandbox to production. |
| Data Stream | A configured ingestion feed bringing data into Data 360 from a connector, on a batch or streaming schedule. |
| Dataspace | A logical partition of Data 360 data. **Required when a SOQL query targets a DLO** — omit it and the query returns zero records silently, with no error. |
| DLO (Data Lake Object) | The stored, source-shaped table in the data lake created from a data stream — raw material awaiting harmonization. Does *not* share Platform object semantics. |
| DMO (Data Model Object) | A standardized object in Data 360's canonical data model that DLOs are mapped into, enabling cross-source consistency. |
| DSO (Data Source Object) | Representation of raw data exactly as it arrives from the source, before any mapping. |
| Federated Search | Querying a source **live at search time instead of ingesting and indexing it**. Always fresh and no data duplicated, but bound by the source's own rate limits. Agentforce Coworker federates **Slack** (180 queries/min per user) while *ingesting* Google Drive and SharePoint on a 1 hr incremental crawl — the same freshness-vs-latency trade-off as zero-copy federation. |
| Harmonization | Mapping disparate source fields into the standard data model so "email" from five systems becomes one consistent attribute. |
| Identity Resolution | Matching records across sources into one unified individual using match rules and reconciliation rules. Under profile-based pricing, its quality is a **direct recurring cost lever**. |
| Intelligent Context | Automatic extraction of unstructured content (PDFs, tables, images, flowcharts) into grounding data via a low-code pipeline. The same document can be interpreted from multiple business perspectives. |
| Lakehouse | Architecture combining a data lake's cheap open storage with a warehouse's query performance and governance. |
| Lakehouse Federation (Databricks) | Databricks' feature for querying an external system as if it were a native table. The mechanism behind **Data 360 File Sharing into Unity Catalog** — the *inward* path, where a Databricks notebook reads Salesforce data in place. Do not confuse with Data 360's own zero-copy federation, which points *outward*. |
| Match Rules | Criteria (exact or fuzzy — email, name+phone, etc.) that decide when two records represent the same person. |
| OSI | A vendor-neutral, YAML-based open-source standard for interoperable semantic models, metrics and relationships. Core spec finalized February 2026. |
| Profile (billing sense) | A **unified individual after identity resolution** — the unit Data 360 is priced on (~$240 per 1,000 baseline). Not a raw source row, so duplicates inflate a recurring bill. |
| Reconciliation Rules | Rules that pick the winning value (most recent, most frequent, source priority) when matched records conflict. |
| Retriever | A configured query against a search index or data graph that fetches the most relevant content to ground a prompt — Salesforce's RAG building block. |
| Search Index | Unstructured content (PDFs, transcripts, knowledge) that Data 360 has chunked and embedded so it's semantically searchable. |
| Segment | A defined audience slice built from profiles, attributes and insights — the unit you activate to other systems. |
| Semantic Layer | A governed layer of business definitions (what counts as "revenue") between raw data and consumers. **Tableau Semantics** is the Salesforce implementation: an agent asked "what was churn last quarter" gets the company's definition rather than inventing one. |
| `SET OPTIONS` | SOQL clause (Summer '26) specifying the Data 360 dataspace and controlling `NULL` / empty-string handling. Goes at the **very end** of the query. |
| STDM (Standard Data Model) | Salesforce's prebuilt Data 360 schema, so data landing from different sources arrives in a shape the platform already understands instead of one you map by hand. Agentforce writes **production agent session traces** as STDM records — which is why debugging a live agent is a Data 360 query. |
| Unified Profile | The single individual record produced after identity resolution, linking all source records and behaviors. |
| Unity Catalog | Databricks' governance layer for data and AI assets. **Salesforce Data 360 File Sharing into Unity Catalog** (GA October 2025) registers Data 360 objects as shared files that Databricks SQL reads directly, authenticated by **IAM Workload Identity Federation** — secretless, no long-lived key on either side. |
| Vector Database (Data 360) | Data 360's built-in store of embeddings for unstructured content, powering semantic search and grounded AI answers. |
| Zero Copy / BYOL | Federation pattern: query data in Snowflake, BigQuery, Databricks or Redshift in place — bring your own lake — without copying it into Data 360. |

## Platform & integration (Summer '26)

| Term | Definition |
|---|---|
| `accessCheck` | Agent Skill frontmatter declaring the **org permission** a skill needs (e.g. `userPerm: "ManageSandboxes"`), so it fails fast instead of dying inside a REST call. Sibling of `cliTools`, which declares the local CLI it needs. Both added to `forcedotcom/sf-skills` in late July 2026. |
| `AccessLevel` | The Apex enum that makes an operation's execution context explicit — `AccessLevel.USER_MODE` or `AccessLevel.SYSTEM_MODE`. Passed to `Database` methods and `Database.queryWithBinds`. At API 67.0 user mode is the default, so this is how you deliberately elevate rather than how you deliberately restrict. |
| Agentforce Vibes IDE | **Formerly Code Builder** — the browser-hosted, cloud-run VS Code environment launched from Setup, carrying the same Salesforce extensions as the desktop. The rename is the trap: 2024–25 material calls it Code Builder and it is the same product. **Coverage gaps** — Professional Edition, Government Cloud, the EU Operating Zone, FedRAMP High and China Cloud — are why **Web Console** exists alongside it. Free in every Developer Edition org since April 2026. |
| ApexGuru | Apex analysis driven by the org's **actual runtime metrics** rather than static rules, so findings are ranked by observed cost. GA since **February 2024**, reachable from the DX MCP server since 2026. **The entitlement is the headline: it ships with Scale Center** — UE production and full-copy sandboxes, Signature Success, Scale Test — and is **not supported on Government Cloud Plus**. Enable at Setup → Scale Center → ApexGuru; reports appear within ~24 hours. |
| Apex Enterprise Patterns | The layered architecture above the trigger handler: **Selector** (all SOQL for one SObject), **Domain** (per-record validation and defaulting), **Service** (a use case spanning objects), and **Unit of Work**. Usually met through **fflib** — `apex-enterprise-patterns` on GitHub, originally FinancialForce's Apex Commons — which is **community-maintained open source, not a Salesforce product**: Salesforce promotes the patterns and ships, supports and versions none of the code. Worth the ceremony on multi-team, long-lived orgs; overhead below that. **Re-read Selector base classes at 67.0** — their `enforceFLS`/`enforceCRUD` flags were written when system mode was the default, so the notable case is now deliberate elevation, not enforcement. |
| Apex Managed Sharing | Granting record access from code by inserting rows into an object's `__Share` table — `ParentId`, `UserOrGroupId`, `AccessLevel`, `RowCause`. The `RowCause` decides survival: a `'Manual'` row is **deleted when the record owner changes**, while a row tagged with an **Apex sharing reason** (custom objects only) survives. Register a `Database.Batchable` recalculation class, or an admin's *Recalculate Sharing* silently wipes every row your code wrote. |
| Apex-Defined Type (ADT) | An Apex class with `@AuraEnabled` members used as a **Flow variable's data type** or an LWC payload — how a Flow holds a shape with no custom object behind it. Distinct from `@InvocableVariable`, which exposes fields to an *action*; a class often needs both and neither implies the other. Since **Winter '26** Flow Data Tables render ADTs, retiring the throwaway-custom-object workaround. |
| `Any API Auth` | The **Summer '26** user permission controlling who may authenticate via SOAP `login()`, **enforced by default in newly created orgs**. The narrow gate in front of a wide retirement: `login()` for API 31.0–64.0 goes away in **Summer '27**, and this is how you find and stop the callers before then. |
| API Catalog | The registry that turns an inbound Salesforce API into something an agent can call. Deploying an Apex class that defines a REST resource **adds its OpenAPI document and metadata to the catalog**, and its methods become available as **agent actions**; optional **extension fields** in the document let the API's owner control that exposure instead of rebuilding it in Agent Studio. Also a documented tool source for custom MCP servers, which makes `Apex REST → OpenAPI → API Catalog → agent action` one pipeline. Parts are still Beta. |
| Briefcase Builder | Where an admin defines which filtered records are primed onto a device for **offline** use in the Salesforce mobile/offline app, including custom objects and related objects **up to three levels deep**. No briefcase, no offline records. |
| Avro (Apache Avro) | The binary serialization format Pub/Sub API event payloads use. Messages carry a **schema ID**, not the schema — a client calls `GetSchema` once and caches it, which is what keeps messages small and what breaks naive clients that never fetch it. A changed event definition means a changed schema. |
| Bulk API 2.0 | The default asynchronous surface for large record volumes — Salesforce batches the payload for you, over an ordinary REST/OAuth framework. Salesforce's own threshold is **more than 2,000 records**. **v1 is legacy, not retired**, and its manual batch-splitting model plus the `Sforce-Enable-PKChunking` header **do not apply to 2.0**. `JobComplete` means processing finished, not that records succeeded. |
| Bulkification | Writing Apex so the cost of a transaction does not scale with the number of records in it: collect keys into a `Set`, do the query or DML once outside the loop, look results up inside it. Not optional — a trigger receives up to **200** records per invocation whether a user clicked Save or a load sent 50,000. |
| Client Credentials Flow | The OAuth flow for server-to-server work with no user present: client ID and secret in, access token out. Its whole security boundary is the **Run As user** configured on the app — point it at a System Administrator and the client secret owns the org. The intended pairing is a free **Salesforce Integration** licence: API-only, no UI login, so integration traffic stays attributable. The alternative with no stored secret at all is **JWT bearer**. |
| Code Analyzer (Salesforce) | A façade over **seven** static-analysis engines — `pmd`, `eslint`, `cpd`, `regex`, `retire-js`, `flowtest`, `sfge` — behind one command, one `code-analyzer.yml` and one 1–5 severity scale. **v4 reached end-of-life in August 2025**: the CLI topic moved `scanner` → `code-analyzer`, the `@salesforce/sfdx-scanner` plugin left the just-in-time install list, and the `run-code-analyzer@v1` GitHub Action still wraps the dead version. **SFGE** (Salesforce Graph Engine) does the cross-file data-flow analysis and is slow enough to need its own pipeline stage. `--severity-threshold` makes it a gate; SARIF output puts findings on the PR diff. |
| CometD / Bayeux | The HTTP long-polling protocol behind the **Streaming API**. **Not retired and with no published end-of-life** — Salesforce *recommends* Pub/Sub API for new external subscribers, which is weaker than a replacement. The proof it is still current: **`lightning/empApi`**, the supported in-org LWC subscriber, is CometD-based. What the docs actually label *(Legacy)* is narrower — **PushTopic** and **generic** events. |
| Composite Graph | The REST resource that raises composite's 25-subrequest ceiling to **500 nodes per graph** (API v50.0+) and makes atomicity **implicit and per graph** — each graph rolls back independently, so one request can carry several that succeed or fail separately. Plain **composite** is the opposite: `allOrNone` is **opt-in**, and omitting it returns HTTP 200 with failures buried in the body. |
| Complex Template Expressions | **Beta at API 66.0+**, and the docs say plainly *"Do not use complex template expressions in production."* Allows a subset of JavaScript — ternaries, optional chaining, comparisons, inline handlers — directly inside an LWC template's `{}`, removing getter boilerplate. Widely written up in 2026 as though it had shipped; it has not. |
| Custom Error (Flow element) | The Flow element that shows an error message you wrote **and rolls the transaction back** — Winter '24, record-triggered flows. The distinction that matters: a **fault path does not roll back**, so it reports the failure while leaving everything already written on disk. `Roll Back Records` (Winter '22) does the rollback without a message but is **screen-flow only**, and reaches back only to the previous screen, because every screen boundary ends a transaction. |
| Custom Lightning Type | The metadata that replaces an Agentforce action's default input form or output text with your own LWC. A folder under `lightningTypes/` with a required **`schema.json`** (the data shape, mirroring the action's `@InvocableVariable` properties), plus optional **`renderer.json`** for output and **`editor.json`** for input. Components bind by `targetType` — **`lightning__AgentforceOutput`** for a renderer, **`lightning__AgentforceInput`** for an editor. **Overrides register per channel** (`lightningDesktopGenAi`, `enhancedWebChat`, `lightningMobileGenAi`, `experienceBuilder`) with no inheritance, so registering one leaves the others on the default UI. |
| `Database.Cursor` | A server-side handle to a SOQL result set, paged with `fetch(position, count)` and surviving into later transactions for **2 days** — the Queueable-chain counterpart to a batch `QueryLocator`. **GA since Summer '24 (API 61.0), and not a row-limit escape hatch**: each `fetch()` costs a SOQL query and its rows count against the row limit. 50 M rows per cursor, 100 fetches per transaction, 10,000 cursors per org per 24 h. |
| `dist-tag` (npm) | A named pointer to one published version of an npm package. **They are not ordered by version** — `@salesforce/cli` currently has `latest` at 2.145.6, `latest-rc` at 2.146.3 and `nightly` at 2.147.3. `npm install` follows `latest`, so "the newest published version" and "the version you get" are routinely different, and a security patch can be published and still be unreachable from a plain install. |
| `Database.Stateful` | The marker interface that makes a batch class's **instance** member variables persist across `execute()` chunks. **Static variables still reset at every chunk** — which is why a running total so often ends up equal to the last chunk's count. |

| Draft Record | A record created or edited in the Salesforce mobile app **while offline** — held in a local queue with no server Id until it synchronises. The consequence people miss is timing: triggers, validation rules and flows run **at sync, not at save**, so an offline save can be rejected hours later and out of context, which is what makes client-side validation mandatory in an offline component. |
| Dual-Use Certificate | One certificate, issued from a single public-CA root, serving both website SSL and client authentication. **No longer issuable** — a public CA can no longer maintain a root that does both — so any **mutual TLS** integration built on one fails at its next reissue and needs a separate client-authentication-only certificate. Arrives alongside the validity collapse (**200 days from 15 Mar 2026, 100 from 15 Mar 2027, 47 from 15 Mar 2029**) and Salesforce's instruction to **stop certificate pinning** in favour of trust stores kept current with the Mozilla Pinset. |
| Dynamic Actions | Actions configured on the Lightning record page's Highlights Panel with per-action filters (field values, user, device type) instead of in the page layout's action section. | Edge Network (Salesforce) | Routing that terminates TLS at points of presence near the caller, cutting round-trip latency. A **routing layer, not an address** — you still call the org's My Domain host. Enabling it does nothing for a client still calling an instanced hostname. |

It changes a failure mode, not just a ceiling: a runaway chain that used to stop with a `LimitException` now merely slows down. Track it with `DailyAsyncApexElasticExecutions` and `DailyAsyncApexProcessed` in `System.OrgLimits.getMap()`. |
| Event Relay | Configuration that forwards platform events and Change Data Capture from the Salesforce event bus into **Amazon EventBridge** — a channel selects the events, a relay binds it to a partner event source. **EventBridge is the only destination**; there is no Azure or Google equivalent. The point is that there is **no subscriber to run**: no gRPC client, no replay store, no restart logic. The partner event source must be **associated with an event bus** on the AWS side or events are dropped while the Salesforce side reports healthy, and the **72-hour** retention still applies to a relay left in an error state. |
| External Client App (ECA) | The successor to the connected app, and the object every modern OAuth flow is configured on. It is also the required setup object for **hosted MCP servers**. A new ECA takes **up to 30 minutes** to become usable, and the failure before then looks exactly like a wrong client ID. |
| External Credential | Half of the Winter '23 named-credential model: it holds the **authentication protocol** (OAuth 2.0, JWT, AWS Signature v4, Basic) and its **principals**, which map to permission sets — so "who may call this system" becomes a permission-set assignment. The paired **named credential** holds the base URL and points at it. **Legacy named credentials are deprecated** and have no principals to map at all. |
| `findSessions` | The documented entry point in the `agentforce-observe` skill for locating a specific production agent conversation in Data 360 STDM trace records before analysing it. Companion reference: `stdm-queries.md`. |
| External Service Registration | The metadata a **Flow HTTP Callout** generates behind the scenes, alongside Apex classes and an org-wide invocable action — which is why configuring a callout in one flow makes it available to every flow, and to Agentforce. The response schema is **inferred from a single pasted sample response**, so a field absent from that sample does not exist to the action. Verbs went GA in stages: `GET` Summer '23, `POST`/`PUT`/`PATCH`/`DELETE` **Winter '24**. |
| Flow Approval Process | The current approval model: an orchestration of **stages**, each holding **approval steps** (which assign an *approval work item* to a user, group or queue) or **background steps**. Routes on any data or business rule, extends with Apex, and tracks in **Approval Submissions** / **Orchestration Runs**. Since **2026-02-18** Flow Orchestration is a standard flow type — no add-on, no usage-based run limits. **Classic approval processes are not retired**; the docs were renamed *Classic Approval Processes*. |
| Flow Trigger Explorer | The Setup view (**Spring '22**) that shows every record-triggered flow on an object in the order it will run, and lets you reorder them. Order comes from each flow's **Trigger Order**, a number **1–2000** in Advanced Settings; ties fall back to created/last-modified order. It only orders flows of the **same trigger type on the same object** — an after-save flow can never be made to run before a before-save one. |
| Governor Limit | A per-**transaction** ceiling the multitenant runtime enforces on Apex — 100 SOQL queries (200 async), 50,000 rows, 20 SOSL queries, 150 DML statements, 10,000 DML rows, 10s/60s CPU, 6/12 MB heap. | Grant Access Using Hierarchies | The switch deciding whether a record's access flows **upward** to everyone above its owner. | gRPC | The HTTP/2 RPC framework **Pub/Sub API** is built on. Practical consequence for a design review: it needs a generated client from a proto file rather than a REST call, which is a real adoption cost — and it is what makes explicit **flow control** possible where long-polling had none. |
| Headless 360 | The organizing idea of Summer '26: every major Salesforce capability reachable as an **API, an MCP tool, or a CLI command**, by a human, an app or an autonomous agent. |
| Hosted MCP Server | A Salesforce-hosted MCP server exposing org capability to any MCP client over standard OAuth. Standard servers (SObject, Data 360, Tableau) are **GA**; custom servers **respect the org's full sharing and security model**, which the API 67.0 user-mode default makes structural rather than aspirational. Built from Apex actions, autolaunched flows, Apex REST, `@AuraEnabled` methods, the **Named Query API**, Prompt Builder prompts, whole Agentforce agents, or the **API Catalog**. Connection is via an **External Client App** with the **`mcp_api`** scope, and the flow is **authorization code only — there is no machine-to-machine option**, so "the agent runs as a service account" is not currently available. Servers are **inactive by default**; audit with Event Monitoring on `API_CLIENT_CATEGORY = SALESFORCE_HOSTED_MCP`. |
| HTTP 410 GONE | What a **retired** Salesforce API version returns. The distinction from deprecation is the whole point: a retired version does not degrade or fall back to a supported one — the integration stops. Versions **21.0–30.0** were retired in Summer '25; the floor is **31.0** and **no next wave is announced**. |
| Idempotency Key | A stable identifier a caller sends on every attempt at one logical operation, so a receiver can recognise a repeat and return the first result instead of doing the work twice. Necessary because **a timeout is not a failure** — it means you do not know whether the work happened — and because every Salesforce event bus is **at-least-once**. The idiomatic platform implementation is a **unique external ID** field: the uniqueness constraint deduplicates and `DUPLICATE_VALUE` is the signal. Upsert on an external ID is the built-in case. Give the key an expiry, or the dedupe table becomes the largest object in the org. |
| Implicit Sharing | Record grants the platform maintains **automatically and unconfigurably** between an account and its children, and between a portal user and their own account and contact. The concrete shape to memorise: with Account OWD Private, a user with edit on an Opportunity gets **read-only** on the parent Account — not none, not edit — and account access can imply contact access. It is why "Private" is not private, and it appears in no sharing rule you wrote, so no configuration review reveals it. |
| Integration Test (Apex) | **Developer Preview at 67.0**, and narrower than the name: the feature is *Apex Integration Tests for **Agentforce and Data 360 Services***, scratch orgs only via the `ApexIntegrationTests` feature. `@IntegrationTest` permits **live callouts**, `IntegrationTest.commitTestOnly()` commits mid-transaction, and `@TearDown` cleans up. It exists because mocking every callout and rolling back all data makes a real agent round trip unassertable. |
| `inherited sharing` | The Apex class modifier that takes the **caller's** sharing context and falls back to `with sharing` when the class is entered directly. The correct choice for a shared selector or utility now that a keyword-less class no longer inherits anything. Note that **inner classes never inherit the outer class's declaration** — they take the default. |
| Lightning Data Service (LDS) | The **shared client-side record cache** behind `lightning/uiRecordApi` — `getRecord`, `createRecord`, `notifyRecordUpdateAvailable` — and the `lightning-record-form` family. Several components wired to one record produce one request and one normalised copy, and it enforces the user's CRUD, FLS and sharing server-side, so an LDS-only component has no sharing decision to get wrong. Record-shaped by design: addressed by ID, one-hop spanning fields, no arbitrary `WHERE`. **The only client-side create/update/delete path** — the GraphQL wire adapter cannot write. |
| Lightning Message Service (LMS) | Cross-DOM publish/subscribe over a **message channel**, which is *metadata* (`.messageChannel-meta.xml`, with `isExposed`) rather than a JavaScript singleton — the property that makes it defensible where an Aura-era pubsub module was not. `MessageContext` must be obtained by `@wire`. **Default scope is the active navigation context**, so inactive console tabs and the utility bar hear nothing without `APPLICATION_SCOPE`. Narrowed twice since 2026: State Managers handle shared *values* better, but LMS remains the only channel that also reaches Aura and Visualforce. |
| Lightning Web Security (LWS) | The sandbox that **replaced Lightning Locker as the default — not by retiring it.** LWS is default only for orgs created **Winter '23+**, GA for all orgs since **Summer '23**, and still a Session Settings checkbox. Architecturally it **virtualizes the browser per namespace** and applies *distortions* (altering specific native APIs) where Locker wrapped objects in secure proxies — so standard JavaScript and third-party libraries mostly work. It is **namespace isolation, not a firewall**: storage and cookies are silently namespaced, cross-namespace mutations are absorbed, and the genuinely blocked set is short (`document.write()`, `Worker()`, `ServiceWorkerContainer`, `window.find()`, XSLT). At **67.0 it blocks the `data:` URI scheme** on an anchor's `href` — use a `blob:` object URL. CSP, the LWC framework and your own XSS handling are separate concerns commonly misattributed to it. |
| Live Preview / LWC Component Preview | The org-backed local development loop: `sf lightning dev component｜app｜site` serves your components locally while proxying a **real org**, so wire adapters, `@salesforce/*` imports and Apex resolve against real data, and saving hot-reloads instead of deploying. **LWC Component Preview is GA at API 67.0**; the VS Code extension was renamed **Local Dev → Live Preview**. Not to be confused with the retired 2019-era `sfdx force:lightning:lwc:start`, which was a *different*, mock-backed, off-org product. |
| LWC State Manager | **GA at API 67.0.** A module built with `defineState` from `@lwc/state` that holds shared state outside any component: `atom()` is one reactive value, `computed()` derives from atoms and recomputes lazily, `setAtom()` is the only way to write, and multiple writes in a tick batch into one notification. Built-ins include `lightning/stateManagerRecord`. **Sharing is by context, not by page** — a component instantiating the manager becomes the provider for its subtree, descendants reach up with **`fromContext`**, and anything outside that subtree gets nothing, which is why it does **not** replace LMS. Read through `.value`. The first new answer to cross-component state since LMS — it displaces prop drilling and narrows what `@track` is for. Platform GA notwithstanding, the **`@lwc/state` npm package is still `0.x`**. |
| `lwc:dom="manual"` | The directive marking a template element whose children are inserted by code the framework does not control — required so the **synthetic shadow** polyfill can still scope styles into it. The cost is usually understated: its content is outside reactivity, outside accessibility management **and outside template sanitization**, so `innerHTML` with server data there is an XSS hole rather than a styling shortcut. |
| `mcp_api` | The OAuth scope granting access to **Salesforce hosted MCP servers only** — created specifically so an MCP client need not be given `api`, which carries the entire Platform API surface including Metadata and Tooling. Requested on an **External Client App** alongside `refresh_token`. The scope is the whole reason an MCP connection can be narrower than a generic API integration. |
| Metadata API | The **SOAP-only**, file-based, asynchronous API for deploying and retrieving org configuration — ~400 types, `package.xml` plus a zip. Every deployment tool is a client of it: the `sf` CLI, DevOps Center, the VS Code extensions, every CI pipeline. This is the single biggest reason **SOAP persists**. Contrast **Tooling API**. |
| Metadata Coverage Report | The authority on whether a metadata type can be moved at all — `developer.salesforce.com/docs/metadata-coverage`, **per API version and per channel** (Metadata API, source tracking, Change Sets, unlocked packages and managed packages have separate columns). | Mixed DML Exception | Thrown when one transaction writes both a **setup** object (`User`, `Group`, `GroupMember`, `PermissionSetAssignment`, `QueueSobject`) and a standard or custom object. Split the second half into an async context; in tests, `System.runAs()` also creates the boundary. |
| Muting Permission Set | **The only construct in the Salesforce permission layer that subtracts.** Created from inside a permission set group (never from the Permission Sets list), belonging to exactly one group, and removing a permission **within that group only** — the underlying permission set is untouched and stays reusable elsewhere. Its hard limit is the reason it so often "doesn't work": **muting cannot reduce access below what the profile grants**, because effective access is still the union with the profile. |
| Named Query API | A REST resource exposing **parameterized SOQL as a named, reusable operation** rather than a query string a caller composes. One of the documented tool sources for a custom MCP server — which is the point: an agent gets a query it is allowed to run, with the parameters it is allowed to vary, instead of the ability to write arbitrary SOQL. |
| `NavigationMixin` | The superclass — `extends NavigationMixin(LightningElement)` — giving a component `Navigate` and `GenerateUrl`. A component describes a **page reference** (a typed object such as `standard__recordPage` or `standard__objectPage`) and the service resolves it for Lightning Experience, a console subtab, mobile or an Experience Cloud route, which is why hand-built URLs are a defect rather than a style choice. `state` values must be **strings** and custom keys must be prefixed **`c__`** or they are dropped silently. Prefill via `encodeDefaultFieldValues` works **only** on `actionName: 'new'`. |
| Permission Set Licence (PSL) | An add-on entitlement assigned to a user **separately from the permission set that requires it** — which is why "I assigned the permission set and nothing happened" is so common. Salesforce's own framing: *permissions are locks, licences are rings of keys*; a permission the user licence has no key for cannot be granted at all, and the checkbox is typically absent rather than unchecked. A user holds exactly **one user licence** but any number of PSLs and feature licences. User Access Policies can assign PSLs, and log a shortfall to *Recent User Access Changes* rather than raising an error. |
| PK Chunking | Splitting a large bulk query into chunks by record ID. **The `Sforce-Enable-PKChunking` header is a Bulk API *v1* mechanism** — in **Bulk API 2.0** you set neither batch sizes nor that header, and chunking is handled server-side. Copying v1 chunking advice into a 2.0 client does nothing at all. |
| Pub/Sub API | The gRPC/HTTP2 event transport — **Avro** binary payloads, `Subscribe` / `ManagedSubscribe` / `Publish` / `GetSchema` / `GetTopic`, and **pull-based flow control** (`num_requested`) so a slow subscriber applies backpressure instead of falling behind. **Recommended for new external subscribers; it retired nothing** — see **CometD / Bayeux**. | PushTopic | A SOQL query you subscribe to, and **one of the two things Salesforce actually labels *(Legacy)*** in the event stack (the other is generic events). | Public Group | The reusable **grantee** container — users, roles, roles-and-subordinates, territories and **other public groups**, since groups nest. Membership is queryable via `Group` and `GroupMember`. Two traps: *Role and Subordinates* includes **portal and community roles** where *Role and Internal Subordinates* does not, and membership changes lock the group maintenance tables — **granular locking** is what Salesforce enables to make a large role-hierarchy realignment survivable. |
| Queueable Apex | The default async mechanism, displacing `@future`: an object with typed member variables, a job ID returned by `System.enqueueJob`, one child job for chaining, a 0–10 minute delay, `AsyncOptions.DuplicateSignature` to suppress repeats (a second enqueue throws `DuplicateMessageException`), and `System.attachFinalizer` for recovery. | Reactive Screen Component | A screen-flow component that reads another component's live value and recalculates **without a Next click** — Beta Summer '23, **GA Winter '24**, requiring flow API **59.0+**. | Release Update | A behaviour-changing platform change listed individually under Setup → Release Updates, each carrying a **Complete Steps By** release. **Not an advisory** — on that release Salesforce enforces it whether or not you acted. Pinning Apex or an integration to an older API version does **not** opt you out, because the change is to org behaviour, not to an API version. |
| Replay ID | An **opaque** marker of an event's position in the stream — a bookmark, not a sequence number, so arithmetic on it is meaningless. Store the last one **after processing, not on receipt**, or a crash mid-processing skips an event permanently. Useless past the **three-day** retention window. **Managed subscriptions** move this bookkeeping to Salesforce. |
| Restriction Rule | **The only mechanism that reduces record access** — GA **Winter '22**, and the reason "a user's access is the union of everything that grants it" stopped being a complete answer. | `Trigger.operationType` | The `System.TriggerOperation` enum (`BEFORE_INSERT`, `AFTER_UPDATE`, …) that lets a trigger body be a single `switch on` dispatch into a handler class. | Unit of Work (Apex) | The layer of **Apex Enterprise Patterns** that owns every DML statement: register work with `registerNew` / `registerDirty` / `registerRelationship`, then one `commitWork()` resolves insert order from a declared `List<SObjectType>`, fills child lookups with parent Ids, and issues **one DML statement per object type** inside a single savepoint. Deletes the "insert parents, collect Ids, stitch children" ritual. Two limits: it groups *statements*, so the 10,000-row DML ceiling is unchanged, and one bad record rolls back everything registered — wrong for partial-success batch work. |
| User Access Policy | The declarative joiner–mover–leaver mechanism: criteria over User fields, applied automatically when a user record is **created or updated** into matching. Assigns or removes permission sets, permission set groups, **permission set licences**, managed package licences, and public group and queue memberships. **GA Summer '24**, Enterprise and Unlimited only, **200 active per org**, requiring `Manage User Access Policies`. Four constraints that shape the design: it is **never retroactive** (use the manual one-time application for the existing population), **a policy cannot trigger another policy**, group and queue management reaches **only directly-added members** — not people inheriting through a role, territory or nested group — and *Recent User Access Changes* drops overridden entries, so it is not an audit trail. |
| User Mode | Execution context enforcing the running user's object permissions, FLS and sharing rules. **The default for Apex SOQL/SOSL/DML at API 67.0** — elevated access is now opt-in. |
| User-Defined Type (Apex) | **Not an interface — nothing implements it.** The phrase is the Apex documentation's own term for a plain class used as a typed payload: *"a list of a user-defined type, containing variables of the supported types."* Because the name reads like `Comparable` or `Callable`, people search for a `UserDefinedType` interface that has never existed. Typed interop is three unrelated mechanisms — `@InvocableVariable`, **Apex-Defined Types**, and `equals`/`hashCode` for map keys. |
| `UserRecordAccess` | The queryable object answering *can this user see this record* — `HasReadAccess`, `HasEditAccess`, `HasDeleteAccess`. **It must filter on `RecordId`, and `RecordId IN` accepts at most 200 records per query**, so it does not bulkify like ordinary SOQL: 1,000 records costs five of your 100 queries. It answers a **sharing** question only — `HasEditAccess` can be `true` for a user with no Edit permission on the object. From a **Flow** *Get Records* element it needs one extra precaution: do **not** use *Store All Fields* (Flow retrieves unsupported fields such as `Id` and errors — Salesforce KB `000383422`); select `RecordId` plus the access fields, and enable *When no records are returned, set specified variables to null*, because "no access" **is** the zero-row case. |
| `with sharing` (default) | At API 67.0 a class with no sharing keyword defaults to `with sharing`. Previously it inherited the caller's context, which silently skipped sharing when it was the entry point. |
| `WITH SECURITY_ENFORCED` | **Retired — no longer compiles at 67.0.** Replaced by `WITH USER_MODE`, which handles polymorphic fields, checks the `WHERE` clause and reports every FLS violation instead of the first. |
| `WITH USER_MODE` | The SOQL/SOSL clause enforcing the running user's CRUD, FLS **and sharing** — the replacement for `WITH SECURITY_ENFORCED`, and already the behaviour of an untagged query in a class compiled at 67.0. Write it anyway: it survives an API-version bump as a statement of intent. Its `Database`-method equivalent is the `AccessLevel` argument. |
| Web Console (Beta) | An IDE running **inside the org** in the browser — Apex, LWC, anonymous Apex, trace flags and debug levels in one place. Open beta from **14 April 2026**, enabled at Setup → Development, available across orgs and editions on admin opt-in, which is precisely where **Agentforce Vibes IDE** is not. Supports **Salesforce-provided extensions only**. Frequently framed as the end of the **Developer Console** — which is labelled *legacy* but has **no announced retirement date**. |
| Zip-slip | A path-traversal attack on archive extraction: an entry whose stored path escapes the target directory (`../../../.git/hooks/pre-commit`), so unzipping writes where the extractor never intended. Fixed in `@salesforce/source-deploy-retrieve` **13.0.1** (`W-23558165`) for static resources of `contentType` `application/zip` / `application/jar` during metadata→source conversion. The lesson beyond the CVE-shaped fact: **`sf project retrieve` is an inbound trust boundary**, executing org-controlled bytes on your machine. |

## Data & AI Core

| Term | Definition |
|---|---|
| Attention | The core transformer operation: for each token, score how relevant every other token is, and blend information accordingly. |
| Chunking | Splitting documents into pieces before embedding — chunk size and overlap strongly affect retrieval quality. Usually the single biggest lever on RAG quality. |
| Data Lineage | Tracking where data came from and how it was transformed — key for trust, debugging and compliance. |
| Data Pipeline | An automated flow that moves and transforms data between systems on a schedule or trigger. |
| Embedding | A numeric vector representing meaning; similar texts map to nearby vectors, enabling semantic comparison. |
| ETL / ELT | Pipeline patterns: transform before loading (ETL) vs load raw then transform inside the warehouse (ELT, the modern default). |
| Few-Shot Prompting | Steering a model by including a handful of worked examples in the prompt instead of retraining it. |
| Fine-tuning | Further training a model on domain data to shift its behavior — contrast with RAG, which supplies knowledge at runtime. |
| Hallucination | Confident but false model output; mitigated by grounding, RAG, citations and validation. |
| Idempotency | Property that re-running a pipeline or action produces the same result — essential for safe retries, and for agents that may repeat an action after a timeout. |
| Inference | Running a trained model to produce output; what you pay for per token on every API call. |
| LLM (Large Language Model) | A model trained on massive text corpora to predict tokens, capable of reasoning, generation and tool use. |
| Multi-Agent System | Multiple AI agents interacting — cooperating or competing — to solve a task no single agent handles well; the theory behind orchestrator-worker designs. |
| Prompt Injection | Attack where malicious instructions hidden in data (an email, a web page) hijack an agent — a core security concern in tool-using systems, and a Trust Layer control point. |
| RAG (Retrieval-Augmented Generation) | Pattern: retrieve relevant content, inject it into the prompt, and generate an answer grounded in it — the antidote to hallucination. |
| Semantic Search | Retrieval by meaning using embedding similarity rather than keyword matching. |
| Temperature | Sampling parameter controlling randomness: low = deterministic and repeatable, high = varied and creative. |
| Token | The unit models read and write — roughly ¾ of an English word. Context limits and API pricing are measured in tokens. |
| Transformer | The neural architecture behind modern LLMs, built on attention — the mechanism that lets a model weigh which parts of the input matter for each output token. |

## AI research & benchmarks

> Salesforce AI Research's evaluation line. Running detail lives in [05-release-radar/ai-research-and-benchmarks.md](05-release-radar/ai-research-and-benchmarks.md).

| Term | Definition |
|---|---|
| AnchorBench | Benchmark for **long-horizon** persona stability, released 2026-07-27 under **CC BY-NC 4.0** (code included — blocks client work). 2,008 conversations, 27 personas, **85–130 sessions each**. Headline findings: user-state changes recalled at **chance (~0.25)**, no memory setting wins (0.430–0.459), and emotional vulnerability exposes more failures than explicit attacks. **Paper is not on arXiv** — every number comes from a README. |
| CRMArena / CRMArena-Pro | The CRM-work benchmark, **accepted to TMLR**. | Enterprise Deep Research (EDR) | Salesforce AI Research's **steerable** multi-agent research system (2025-10-24): a Master Planning Agent decomposing a query over four specialised search agents. *Steerable* = a human redirects mid-run rather than judging only the output. The first-party reference architecture behind Multi-Agent Orchestration's shape. |
| GIFT-Eval | Salesforce AI Research's **general time-series forecasting** benchmark, Apache-2.0. Seven frequency ranges, seven domains, a fixed **98 dataset configurations** per submission. Notable because competitors submit to it — including **Google Cloud AI Research** — which makes it neutral industry infrastructure rather than a vendor marketing surface. |
| LoCoBench-Agent | Long-context software-engineering benchmark ([arXiv 2511.13998](https://arxiv.org/abs/2511.13998)): 8,000 scenarios, 10 languages, up to 50 turns, **10K–1M tokens**. Two findings: long context degraded **less** than expected, and comprehension trades off against efficiency — so an agent that explores exhaustively is not simply better, it is more expensive under Flex Credits. |
| MFCL Audio | Function-calling benchmark evaluated **from speech**, not from a transcript — **ICML 2026**, 6,200 expert-verified tasks, two suites (**Text Audio** pipelined, **True Audio** end-to-end). Isolates **perception errors**, which corrupt tool-call *arguments* rather than intent. Grading is deterministic (AST-based), with no LLM judge. |
| `model_type` (GIFT-Eval) | The self-declared class in a submission's `config.json`. Three values seen: **`zero-shot`** (never trained on the series), **`pretrained`** (training mixture touched the benchmark's histories with test regions excluded), **`agentic`** (an orchestrator picking among forecasters). Nothing enforces the choice, and `agentic` **does not imply an LLM** — EXAONE-Forecast-Agent routes with XGBoost. |
| Persona collapse | A model drifting off its assigned role, boundaries, values and communication style over a long conversation. Distinct from **trajectory recall** — AnchorBench's central finding is that the two come apart. |
| `replication_code_available` | A field in every GIFT-Eval submission's `config.json`. Read it before quoting a leaderboard position: of the five models merged 2026-07-31, **only one declared `"Yes"`**. Its sibling `testdata_leakage` is **self-declared, not audited**. |
| Computer-use agent | An agent that operates software through its **user interface** — screenshots, accessibility tree, DOM — driving a mouse and keyboard rather than calling APIs. The modality **SCUBA** measures, and the one Agentforce does *not* use. SCUBA's result is the argument for the alternative: give an agent invocable actions and MCP tools, not a cursor. |
| SCUBA | **Salesforce Computer Use Benchmark** ([arXiv 2509.26506](https://arxiv.org/abs/2509.26506), September 2025). **300 task instances** drawn from real user interviews across three personas — platform admin, sales rep, service agent — run in **real Salesforce sandbox orgs**. Action spaces of **19** (browser-use) and **15** (computer-use) actions via Playwright and PyAutoGUI; **milestone-based** scoring, so partial progress counts. Headline: **open-source agents under 5%, closed-source ~39% zero-shot**, and a sharp drop moving from generic desktop benchmarks like OSWorld into enterprise CRM. |
| Trajectory recall | Whether a model can distinguish what actually happened in a conversation from a plausible alternative that did not. Measured by AnchorBench's Trajectory Probe with four-option counterfactuals. The support-agent failure it predicts: the customer said at turn 3 they had cancelled, and at turn 40 the agent still acts on the old state. |
| Zero-shot forecasting | Forecasting a time series the model was never trained on — GIFT-Eval's target capability, and the forecasting analogue of a language model answering a question it never saw. |

| Headless Identity | API-first authentication for Experience Cloud: **Headless Login, Registration, Forgot Password** and **Passwordless** APIs let a custom (off-platform) front end run the whole auth journey without redirecting to a Salesforce-hosted login page. Backed by Customer Identity; the APIs are exposed **through an Experience Cloud site**, so even a fully headless build must provision one. The auth cornerstone of a decoupled front end. |
| LWR (Lightning Web Runtime) | The **default** runtime for new Experience Cloud sites; Aura templates are legacy but **not retired** (only two templates, *Build Your Own (LWR)* and *Microsite (LWR)*, are LWR). LWR sites are **built and served** — compiled to static assets at publish, pushed to the Salesforce **CDN** — not rendered per request like Aura. SSR was delivered by **Experience Delivery**, which never left Beta and is **being discontinued in Winter '27**; it is **already closed to new enablement**, and orgs already on it run until **October 2026**. Treat static build + CDN as the entire performance story. A component touching `window`/`document` at module scope breaks the build; guard with `import.meta.env.SSR`. Note **LWR ≠ enhanced LWR** — different metadata types. |
| Enhanced Chat (formerly Messaging for In-App and Web) | The current mechanism for embedding chat — human-routed or an **Agentforce Service Agent** — on a site or app: a **Messaging Channel** → **Embedded Service Deployment** → **Embedded Messaging** component, routed via Omni-Channel. **Renamed from *Messaging for In-App and Web* in June 2025**; **Enhanced Chat v2** shipped Winter '26 (24 Oct 2025) as the Agentforce-first UI, attaching a new deployment to an existing channel. Replaces legacy **Chat / Live Agent, retired 14 February 2026**. Salesforce docs still carry the old name in places — expect both. On a **public** site the conversation runs as the **guest user**, making an embedded agent the platform's highest-risk surface (unauthenticated input + guest data + reasoning engine) — the Einstein Trust Layer and action allow-lists are mandatory, and the agent is a new line item on the public-site exposure audit. |
| Mobile Publisher | Salesforce add-on that packages an Experience Cloud site (or the Salesforce app) as a **branded native iOS/Android app** — your icon, name and store listing, with push and biometric login. **Licensed per app**, submitted through **your own** Apple/Google developer accounts and subject to store review. Native/branding changes need resubmission; content published to the live site appears without it. The alternative, **PWA** delivery, trades store presence and native APIs for instant updates and zero store friction. |

*Added in SF phase 20 (Platform Cache & the event bus gaps).*

| Term | Definition |
|---|---|
| Platform Cache | Tenant-scoped in-memory key-value store that outlives the transaction — `Cache.Org` (all users, TTL up to **48 h**, default 24 h) and `Cache.Session` (one session, TTL up to **8 h**, and dies with the session whichever comes first). **100 KB** per item, **50-character** keys, minimum **1 MB** partition. Capacity is **EE 10 MB · UE/Performance 30 MB · Developer 0 until a 10 MB trial is requested · Professional none**; more is bought in 10 MB blocks. The design constraint is that it is **not storage**: keys are evicted **least-recently-used** whenever a partition fills, so a `null` return is the normal path, not an error. Enforces neither FLS nor sharing on read. |
| `Cache.CacheBuilder` | Apex interface that removes the check-then-populate branch from cache code — implement `doLoad(String key)` and the platform calls it **only on a miss**. The idiomatic way to use Platform Cache, and the answer to the miss-handling mistake everyone makes once. |
| Standard-Volume Platform Event | The pre-Spring '19 platform event type. **Uncreatable since Spring '19**, so every one in existence predates it; **no support, no bug fixes**; **retirement announced** (Help **002280033**) with a migration tool to high-volume by Summer '26. The Help article reads **Winter '27** and published round-ups read **June 2027** — verify before quoting. Not a live alternative to high-volume; high-volume is the only buildable option. |
| Event Delivery Allocation | The **per rolling 24-hour** meter on platform events — UE/Performance **50,000**, EE **25,000**, Developer **10,000** — spent **only** by Pub/Sub API and CometD clients, `empApi` components and event relays. **Apex triggers, flows and Process Builder consume none of it.** Distinct from the **publish** allocation, which is metered **per hour** (250,000 EE and above, 50,000 Developer). High-volume platform events and **Change Data Capture share one delivery pool**. |
| `EventBusSubscriber` | Queryable object representing an **in-org** event subscriber — a trigger, flow or process — carrying `Position`, `Retries`, `LastError`, `Topic` and `Type`. It **excludes CometD and Pub/Sub API subscribers** entirely. A climbing `Retries` is the only early warning before a subscriber hits ten runs and stops. Its external-facing counterpart is `PlatformEventUsageMetric`; the two cover disjoint halves of the bus. |
| `PlatformEventUsageMetric` | Queryable usage counter (API **50.0+**) for `PLATFORM_EVENTS_PUBLISHED`, `PLATFORM_EVENTS_DELIVERED`, `CHANGE_EVENTS_PUBLISHED` and `CHANGE_EVENTS_DELIVERED`, retained **at least 45 days** and updated **hourly** — retrospective, never live. Counts external deliveries and ignores in-org subscribers. **Enhanced Usage Metrics (API 58.0+)** is opt-in and adds per-event-name, per-client and 15-minute breakdowns, without which a spike cannot be attributed. |
| Gap Event | A Change Data Capture `changeType` — `GAP_CREATE`, `GAP_UPDATE`, `GAP_DELETE`, `GAP_UNDELETE`, `GAP_OVERFLOW` — published when the platform cannot generate full change detail, carrying header information without the field payload. Not a separate channel. Some picklist field conversions emit a `GAP_UPDATE` for every affected record. A subscriber that does not branch on them diverges silently. |
| `changeOrigin` | `ChangeEventHeader` field carrying `com/salesforce/api/<API_Name>/<API_Version>;client=<Client_ID>`, whose documented purpose is letting an app **detect its own writes and skip them**, avoiding a two-way sync loop. Preferable to filtering on `commitUser`, which only works while the integration owns a dedicated user. |
| Parallel Subscriptions | **GA at Summer '26 (API 67.0)**: spreading one Apex platform event trigger across up to **10 internal partitions**, configured through `PlatformEventSubscriberConfig` with a partition key (a required custom field, or the standard `EventUuid`). **Custom high-volume platform events only** — not standard events, not change events. Order is preserved **within** a partition and **not across** them, which is a permanent trade, not a tuning knob. |

*Added in SF phase 24 (Reading & retiring the legacy tools).*

| Term | Definition |
|---|---|
| Evaluation Criteria | The workflow rule setting deciding which saves are considered at all, and the one with **no Flow equivalent**. Three values: **created**; **created, and every time it's edited**, which fires even when the criteria were *already* true and **cannot carry time triggers** because the record could requeue endlessly; and **created, and any time it's edited to subsequently meet criteria**, the recursion guard, which can. Distinct from *rule criteria*, which decide whether a given save qualifies. |
| Time-Based Workflow Queue | Where a workflow rule's **time-dependent actions** wait, with a computed fire time, monitored at Setup → Monitoring → **Time-Based Workflow**. **Deactivating the rule does not empty it** — pending entries still fire while the record meets criteria, clearing only when processed or when re-evaluation finds criteria false. **A rule with pending actions cannot be deleted**, and time-dependent actions cannot be added or edited on a deactivated rule that still holds them, so the queue sets the real end date of a migration. |
| Switch Activations | The **Migrate to Flow** button that **deactivates the source workflow rule and activates the migrated flow together**. It exists because the migrated flow is created **inactive**: skip this step and a technically complete migration changes no behaviour at all, which is a more common failure than the double-run people are warned about. The tool is GA — Workflow Rules **Summer '22**, Process Builder **Spring '23**. |
| Re-evaluate Workflow Rules after Field Change | A checkbox on a workflow **field update** that re-runs **every** workflow rule on the object. The legacy recursion engine, the reason one save shows the same trigger repeatedly in a debug log, and invisible in aggregate — nothing in Setup lists which field updates have it ticked. Process Builder's counterpart is its **Recursion** option, which allows **five** evaluations of one record per transaction. |

## Salesforce AI Research ships agentforce-adlc, a Claude Code skill set for the whole agent lifecycle

Salesforce AI Research is publicly developing **`agentforce-adlc`** — "Agent Development Life Cycle" — an open toolkit of **Claude Code skills** that drive Agentforce agent development end to end using the **Agent Script DSL** (the human-readable agent-definition language that compiles to portable JSON; see [agentforce-platform.md](../agentforce-platform.md)). The repo was last updated **July 25, 2026**, with substantive commits every day from July 21–24, so this is live development rather than a dormant sample. It ships four skills: `/agentforce-generate` (authoring, org discovery, scaffolding of missing Flow/Apex/permission sets, deployment, safety review across seven categories), `/agentforce-test` (preview sessions, batch tests, real action execution, adversarial probes), `/agentforce-observe` (pull production session traces out of Data 360, find failure patterns, apply fixes), and `/agentforce-secure` (an OWASP LLM Top 10 assessment of the agent). The reason this matters more than a normal sample repo: it is the first coherent, first-party answer to *"what does the SDLC look like when the artifact is an agent?"* — requirements → authoring → safety gate → deploy → adversarial test → production trace analysis → optimization, with each stage automatable from a terminal. Two practical caveats before you build on it: the licence is **CC BY-NC 4.0** (non-commercial — this is not Apache-2.0 like Agent Script itself, so read it before using it on client work), and it needs Python 3.9+, Salesforce CLI v2.x, and an Agentforce-enabled org.

**Why it's worth your time specifically:** it sits exactly on the seam between your Agentforce track and your Claude Code track — one repo that is simultaneously an Agentforce study lab and a real-world example of non-trivial Claude Code skill design.

**Status:** Open source, actively developed (not a Salesforce-supported product). No GA/Beta designation — treat as research-grade tooling. 92 stars / 37 forks / ~90 commits as of the scan.

**Sources:** [SalesforceAIResearch/agentforce-adlc](https://github.com/SalesforceAIResearch/agentforce-adlc) · [Commit history](https://github.com/SalesforceAIResearch/agentforce-adlc/commits/main) · [SalesforceAIResearch on GitHub](https://github.com/SalesforceAIResearch)

## Voice becomes a first-class modality in the ADLC skills

Inside that same repo, the work merged between **July 16 and July 23, 2026** added **voice modality support across the ADLC skills** — including a `VoiceCallId` concept, connection blocks, and default voice behaviours, aligned to an internal effort the commits call "Project Codey Steel Thread 2." Voice support was merged to `main` on **July 23** (PR #39), and on **July 24** a follow-up added **validation of generated assets against the AgentScript SDK** plus fixes from an adversarial review of `agentforce-generate`. In plain terms: an Agentforce voice agent is no longer something you can only assemble by hand in the builder — its script, its call-context variables and its tests can be generated and validated from code. The AgentScript SDK validation step is the quieter but more important change, because it means generated agent definitions are checked against the real language grammar before they ever reach an org, which is what makes automated authoring trustworthy rather than merely fast.

**Why it matters practically:** voice is where Agentforce deployments are heading commercially (a voice action costs 30 Flex Credits vs. 20 for a standard one), and voice agents fail in ways text agents don't — latency, interruption, mid-call handoff. Tooling that can script and adversarially test a voice agent is the difference between demoing one and operating one.

**Status:** Merged to `main` in an open-source research repo — pre-release quality, no Salesforce support commitment.

**Sources:** [agentforce-adlc commit history](https://github.com/SalesforceAIResearch/agentforce-adlc/commits/main) · [agentforce-adlc](https://github.com/SalesforceAIResearch/agentforce-adlc)

## Headless 360 MCP Server enters Beta with about 100 skills

_Gap-fill: announced early July 2026, outside the 72h window, but not previously captured in this radar._

The **Headless 360 MCP Server** went to **Beta in early July 2026**, building on the hosted MCP servers that reached GA in April. MCP (Model Context Protocol) is the open standard that lets an AI client — Claude, ChatGPT, Cursor, a custom agent — call a system's capabilities as tools. What makes this server architecturally interesting is that Salesforce did *not* expose each feature as its own MCP tool. Thousands of flat tool descriptions would force the model to reason over an enormous list before acting, burning context, tokens and latency on every request. Instead the Beta ships roughly **100 "skills"** behind the server — coarser, task-shaped units, the majority of them **Setup operations for admins**, effectively extending Agentforce for Setup to any headless MCP client. Launch coverage includes high-traffic user administration: creating, deactivating, freezing and unfreezing users, resetting or setting passwords, and assigning permission sets and permission set licences. Salesforce says the skill catalogue will grow during Beta to cover cloud-specific business capabilities.

**Why it matters.** This is the same design lesson as the Data 360 MCP server's three facade tools, applied at platform scale: *tool-count discipline is the central design constraint of a large MCP surface*. If you build your own MCP servers, this is the pattern to copy. It also means org administration is now scriptable by an agent — which is a governance question as much as a productivity one, since "an agent can reset passwords and assign permission sets" needs the same scrutiny you'd give a human with those rights.

**Status:** Beta (early July 2026). Hosted MCP standard servers remain GA since April 2026.

## The VA awards Salesforce a 1.6 billion dollar Agentic Enterprise License Agreement

On **July 24, 2026** the U.S. Department of Veterans Affairs awarded Salesforce a contract worth up to **$1.6 billion** over three years — structured as a one-year base with two one-year options — under a construct Salesforce calls an **Agentic Enterprise License Agreement (ELA)**. The scope is Agentforce agents for 24/7 contact-centre support, patient triage and care coordination, with **MuleSoft** and **Data 360** doing the integration and grounding and **Tableau** the analytics. The stated target is cutting average appointment scheduling from **28 days to minutes** across 40,000+ provider services. It follows earlier Missionforce public-sector wins including a $5.6B Army agreement and a $72M Air Force ELA.

**Why a technical note cares about a procurement story.** Two reasons. First, the "Agentic ELA" is a *new commercial packaging* — an enterprise-wide agent licence rather than Flex Credits consumption or per-resolution billing — which is a third pricing model to keep straight alongside the two already in [pricing-and-certification.md](../pricing-and-certification.md). Second, the architecture named in the award (Agentforce + Data 360 + MuleSoft + Tableau) is exactly the reference stack Salesforce is selling everywhere: agents on top of a unified context layer fed by integration, observed through analytics. Deals of this size are what make that stack's roadmap durable, and they're the shape of engagement an AI-Salesforce architect gets staffed on.

**Status:** Announced July 24, 2026. Contract awarded; deployment not yet delivered — treat the 28-days-to-minutes figure as a target, not a result.
